# Лесоруб — агент на живой игре Cognopolis (локальный запуск)

Готовый проект к Модулю 11.5 «Дизайн инструментов» (лекция на сайте курса):
smolagents-агент (`ToolCallingAgent`) с тем же «хорошим» контрактом
инструментов, что вы собрали в мок-лесу ноутбука: `move`, `gather`, `get_map`,
`get_character`, говорящие ошибки `{code, message}`, конверт
`{result, cooldown, character}`. Но здесь инструменты ходят на **реальный API
игры** https://kindomklaster.com и ведут вашего **настоящего жителя** поселения
по его под-токену. Мок-леса тут нет — только живая игра.

Это и есть тезис лекции «tool это контракт»: контракт tools не меняется, а
мозг агента — локальная модель из LM Studio через его OpenAI-совместимый
сервер http://localhost:1234/v1 (ключей не нужно вообще).

## Два набора tools: хороший активен, плохой закомментирован

В `cognopolis_tools.py` — не только рабочие инструменты, но и разбор их
дизайна по чек-листу A→H из лекции: у ключевых строк хорошего набора стоят
пометки, какую букву они закрывают, а ниже закомментирован **плохой** набор —
тот самый god-tool `do_action(action, target)` из Блока 1 ноутбука,
перенесённый на живой API (внутренние имена `relocate`/`harvest_node`,
немые ошибки `{"error": "invalid"}`, `{"ok": true}` вместо конверта).

Эксперимент на пять минут:

1. Прогоните задачу «Добудь одно дерево (wood) и сдай его на склад» на
   хорошем наборе — агент читает ошибки и идёт к цели.
2. Раскомментируйте в `cognopolis_tools.py` блок `build_bad_tools` и одну
   помеченную строку `return build_bad_tools(client)` в начале `build_tools()`
   (ранний return перекроет хороший набор), перезапустите `app.py`.
3. Та же модель, та же игра, та же задача — а агент угадывает строки,
   получает немое `invalid` и ходит по кругу; панель «Персонаж» перестаёт
   обновляться по ходу шагов агента (конверт с `character` выброшен) —
   правду показывают только снимок в начале сообщения и факт-чек в конце.

Поменялся только контракт — в этом весь урок.

## Что нужно, чтобы запустить

1. **Под-токен персонажа Cognopolis** (Character.token вашего жителя; Ратуша →
   вкладка «аккаунт» → «копировать») — его вписывают в поле «Под-токен
   персонажа Cognopolis». Без него агент не работает и ничем не подменяется.
2. **Мозг-модель**: LM Studio с загруженной инструкт-моделью с поддержкой
   tool use (в каталоге помечены значком-молотком; берите 7B+ — маленькие
   4B теряются в навигации по карте).

## Запуск локально (LM Studio, без ключей для модели)

1. Поставьте [LM Studio](https://lmstudio.ai), включите сервер (вкладка
   Developer -> Start server) и загрузите модель 7B+ с поддержкой tool use.
2. Из этой папки поставьте зависимости (нужен Python 3.10+) и запустите:

   ```bash
   cd spaces/module-11-5-agent
   python -m venv .venv
   source .venv/bin/activate        # Windows: .venv\Scripts\activate
   pip install -r requirements.txt
   python app.py
   ```

3. Откройте http://127.0.0.1:7860, впишите под-токен своего жителя, попросите
   «Добудь одно дерево (wood) и сдай его на склад».

Какую модель взять, приложение спрашивает у LM Studio само (переопределить —
переменные окружения `LM_MODEL_ID` / `LM_BASE`).

## Что написать агенту

- «Добудь одно дерево (wood) и сдай его на склад» — базовый сюжет лекции.
- «Покажи карту поселения» — агент позовёт get_map и перескажет мир.
- «Набери камня (stone) и сдай» — маршрут к ближайшему руднику.

В чате видно каждый шаг цикла think -> act -> observe: какие tools агент
вызвал и что они ответили. Обратите внимание на конверт успешного ответа
`{result, cooldown, character}` и на обучающие ошибки `{code, message}` —
`no_resource_here`, `inventory_full`, `at_map_edge`, `character_on_cooldown`,
`invalid_token`: агент читает message и чинит план сам.

Особенности живого мира (по делу, не по контракту):

- карта поселения 7x7 (`get_map` даёт тайлы `tree` → wood, `rock` → stone;
  есть и тайлы с врагами — на них не ходим);
- **склада-депозита нет**: возврат на дом (0, 0) сам разгружает рюкзак на
  склад (в ответе появляется `banked`) — поэтому вместо `deposit` есть
  `get_character` (позиция, рюкзак, hp);
- мир **общий и персистентный**: житель стоит там, где закончил прошлый раз,
  а не обязательно дома.

## Сброс

Реальный мир Cognopolis общий и живой — кнопка «Сбросить» его НЕ трогает
(нельзя). Она очищает только чат и память агента, чтобы начать задачу с
чистого листа.

## Безопасность токена

Под-токен остаётся в этом локальном процессе и уходит только на сам API игры.
Адрес игры зафиксирован на https://kindomklaster.com (для своего Cognopolis-
сервера — переменная окружения `COGNO_BASE_URL`).

## Файлы

- cognopolis_tools.py — оба набора инструментов на живом API Cognopolis:
  тонкий клиент на `requests` (Bearer под-токен), хороший набор
  move/gather/get_map/get_character с пометками по чек-листу A→H и
  закомментированный плохой `do_action` с разбором провалов;
- app.py — модель из LM Studio, агент, чат на Gradio, поле под-токена, панель
  «Персонаж (живой мир)», кнопка «Сбросить»;
- helpers.py — подпорки под слабую модель (затравка-маршрут + факт-чек),
  отдельно от контракта: на сильной модели не нужны;
- requirements.txt — smolagents + клиентские мелочи (openai, requests, gradio).

Мок-лес (сетка 5x5), на котором вы учили контракт офлайн, живёт в ноутбуке
домашки (`notebooks/module-11-5-tool-design/notebook.ipynb`) — здесь его нет
намеренно: этот проект про тот же контракт уже на боевой игре.
