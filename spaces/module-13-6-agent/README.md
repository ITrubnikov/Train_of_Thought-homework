# Лесоруб с умениями — агент на живой игре Cognopolis (локальный запуск)

Готовый проект к Модулю 13.6 «Skills: выученный инструмент» (лекция на сайте
курса). Тезис лекции — **«skill — это инструмент, описанный словами»** —
здесь работает на живой игре: тот же smolagents-агент, что в проекте 11.5
(`move`, `gather`, `get_map`, `get_character`, говорящие ошибки
`{code, message}`, конверт `{result, cooldown, character}`, реальный API
https://kindomklaster.com, настоящий житель по его под-токену), контракт
tools — из 11.5 без изменений. Добавились только файлы `skills/` —
библиотека умений `SKILL.md` — и пятый инструмент `load_skill`, которым
модель сама подтягивает тело умения.

Мозг агента — локальная модель из LM Studio через его OpenAI-совместимый
сервер http://localhost:1234/v1 (ключей не нужно вообще).

## Skills: что здесь нового против 11.5

В инструкции агента попадает только **витрина** — name + description каждого
умения из `skills/*/SKILL.md`. Тело в контексте не живёт: когда задача
совпала с описанием, агент сам зовёт `load_skill` с именем умения и получает
текст с шагами. Это progressive disclosure из лекции — вживую: в чате виден
вызов `load_skill` среди остальных tools, а панель «Библиотека умений»
показывает текущую витрину с диска. В библиотеке два умения: `supply-run`
(пополнить склад деревом) и `scout-map` (разведать поселение, ничего не
меняя в мире).

## Эксперимент «сломай описание»

1. Откройте `skills/supply-run/SKILL.md` и замените description на
   «Помогает с игрой.» (тело не трогайте).
2. Нажмите «Сбросить» и дайте ту же задачу «Пополни склад деревом» —
   `load_skill` не зовётся (или зовётся невпопад): триггер умер.
3. Верните точное описание, снова «Сбросить» — умение подтягивается снова.

Тело не менялось ни на символ — поведение изменилось от одного описания.
Это та же механика, что в ДЗ лекции («описание — триггер, а не
документация»), но на живой игре.

## Что нужно, чтобы запустить

1. **Под-токен персонажа Cognopolis** (Character.token вашего жителя; Ратуша →
   вкладка «аккаунт» → «копировать») — его вписывают в поле «Под-токен
   персонажа Cognopolis». Без него агент не работает и ничем не подменяется.
2. **Мозг-модель**: LM Studio с загруженной инструкт-моделью с поддержкой
   tool use (в каталоге помечены значком-молотком; берите 7B+ — маленькие
   4B теряются в навигации по карте).

## Запуск локально (LM Studio, без ключей для модели)

1. Поставьте [LM Studio](https://lmstudio.ai), включите сервер (вкладка
   Developer -> Start server) и загрузите модель 7B+ с поддержкой tool use.
2. Из этой папки поставьте зависимости (нужен Python 3.10+) и запустите:

   ```bash
   cd spaces/module-13-6-agent
   python -m venv .venv
   source .venv/bin/activate        # Windows: .venv\Scripts\activate
   pip install -r requirements.txt
   python app.py
   ```

3. Откройте http://127.0.0.1:7860, впишите под-токен своего жителя, попросите
   «Пополни склад деревом».

Какую модель взять, приложение спрашивает у LM Studio само (переопределить —
переменные окружения `LM_MODEL_ID` / `LM_BASE`).

## Что написать агенту

- «Пополни склад деревом» — задача-триггер `supply-run`: в чате видно, как
  агент сначала зовёт `load_skill("supply-run")`, а потом идёт по его шагам.
- «Разведай поселение — что где лежит?» — триггер `scout-map`: сводка по
  карте без единого действия-мутации.
- «Добудь одно дерево (wood) и сдай его на склад» — работает и без умения:
  сравните трейс с `load_skill` и без него.

В чате видно каждый шаг цикла think -> act -> observe: какие tools агент
вызвал и что они ответили. Обратите внимание на конверт успешного ответа
`{result, cooldown, character}` и на обучающие ошибки `{code, message}` —
`no_resource_here`, `inventory_full`, `at_map_edge`, `character_on_cooldown`,
`invalid_token`, `unknown_skill`: агент читает message и чинит план сам.

Особенности живого мира (по делу, не по контракту):

- карта поселения 7x7 (`get_map` даёт тайлы `tree` → wood, `rock` → stone;
  есть и тайлы с врагами — на них не ходим);
- **склада-депозита нет**: возврат на дом (0, 0) сам разгружает рюкзак на
  склад (в ответе появляется `banked`) — поэтому вместо `deposit` есть
  `get_character` (позиция, рюкзак, hp);
- мир **общий и персистентный**: житель стоит там, где закончил прошлый раз,
  а не обязательно дома.

Процедуру (дойти → срубить → вернуться → проверить) несёт **skill**: его тело —
реактивный цикл «сравни своё [x, y] с целью и шагни один раз», а не заранее
посчитанный маршрут. Подпорки под слабую локальную модель вынесены в
`helpers.py` отдельно от умения: затравка фактов, факт-чек складом и
`route_hint` — подсказка «куда шагать» до ближайшего дерева. Она нужна потому,
что небольшая 7B даже с хорошим умением путает координаты соседних клеток и
рубит впустую (проверено). Порядок действий всё равно за умением — подсказка
даёт только навигацию. Выключить её на модели посильнее: `WEAK_MODEL_ROUTE=0`
— тогда навигацию целиком ведёт реактивный цикл умения, и видно, как процедуру
несёт именно skill.

## Сброс

Реальный мир Cognopolis общий и живой — кнопка «Сбросить» его НЕ трогает
(нельзя). Она очищает чат и память агента и заодно перечитывает витрину
умений с диска — на этом держится эксперимент «сломай описание».

## Безопасность токена

Под-токен остаётся в этом локальном процессе и уходит только на сам API игры.
Адрес игры зафиксирован на https://kindomklaster.com (для своего Cognopolis-
сервера — переменная окружения `COGNO_BASE_URL`).

## Файлы

- cognopolis_tools.py — инструменты move/gather/get_map/get_character на живом
  API Cognopolis: тонкий клиент на `requests` (Bearer под-токен) + subclass
  `Tool`, конверт и обучающие ошибки как у сервера; контракт tools — без
  изменений против 11.5 (учебные пометки чек-листа A→H и закомментированный
  плохой набор `do_action` остались в проекте `spaces/module-11-5-agent/`);
- skills_runtime.py — учебный парсер SKILL.md (тот же, что в ноутбуке 13.6),
  витрина `skills_index` и инструмент `load_skill`; скриптового селектора из
  ноутбука нет — описание читает сама живая модель;
- skills/ — библиотека умений: `supply-run/SKILL.md` и `scout-map/SKILL.md`
  (frontmatter name/description + тело «шаги / грабли / проверка»);
- app.py — модель из LM Studio, агент с пятью инструментами, чат на Gradio,
  поле под-токена, панели «Персонаж (живой мир)» и «Библиотека умений»,
  кнопка «Сбросить»;
- helpers.py — подпорки под слабую модель (затравка фактов + факт-чек),
  отдельно от скиллов и контракта: на сильной модели не нужны;
- requirements.txt — smolagents + клиентские мелочи (openai, requests, gradio).

Мок-лес и скриптовый селектор, на которых вы учили механику скиллов офлайн,
живут в ноутбуке домашки (`notebooks/module-13-6-skills/notebook.ipynb`) —
здесь их нет намеренно: этот проект про те же скиллы уже на боевой игре.
