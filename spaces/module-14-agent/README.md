# Лесоруб со справочником — agentic RAG на живой игре Cognopolis (локальный запуск)

Готовый проект к Модулю 14 «LlamaIndex — когда у тебя много данных» (лекция на
сайте курса): тот же лесоруб, что вы собирали на smolagents в 11.5 и гоняли
через MCP в 14.5, — но на LlamaIndex, и у агента впервые **два сорта
инструментов**: действия в мире (`move`, `gather`, `get_character`, `get_map`)
и знания (`handbook` — поиск по справочнику поселенца, кускам настоящей вики
игры). Инструменты ходят на **реальный API игры** https://kindomklaster.com и
ведут вашего настоящего жителя по его под-токену.

Это пуант лекции живьём: **классический RAG ищет всегда — агент решает, КОГДА
искать**. Спросите «что теряется при гибели в бою?» — агент полистает
справочник и ответит, не сделав ни шага. Попросите «добудь дерево и сдай» —
пойдёт рубить, а в справочник заглянет, только если засомневается в правилах.
Всё видно в чате: каждый вызов инструмента — отдельная плашка.

Мозг агента — локальная модель из LM Studio через его OpenAI-совместимый
сервер http://localhost:1234/v1 (ключей не нужно вообще). Дропдаун
«Модель-мозг» показывает всё, что есть в LM Studio (● загружена, ○ подгрузится
на лету), «↻ Обновить» перечитывает список без перезапуска.

## LlamaIndex: что здесь нового против 11.5/14.5

- **Инструменты — `FunctionTool`, «функция с паспортом»**: имя из имени
  функции, description из docstring, схема аргументов из type hints
  (`Literal` превращается в enum). Контракт — дословно тот же, что в 11.5
  (конверт `{result, cooldown, character}`, ошибки `{code, message}`), но
  буквы A/B/C чек-листа теперь закрывает сама библиотека — см. пометки в
  `cognopolis_tools.py`.
- **Пятый инструмент — база знаний.** `handbook.py` — вся лестница модуля в
  одном файле: `SimpleDirectoryReader` → `SentenceSplitter` →
  `HuggingFaceEmbedding` (локально, CPU) → `VectorStoreIndex` над
  `knowledge/*.md`. Chroma из ноутбука тут не нужна: корпус крошечный и
  версионируется git-ом — индекс пересобирается на старте за секунды.
- **Две из «трёх дверей к индексу» — переключатель `HANDBOOK_DOOR`.** Дефолт
  `retriever`: агент получает top-3 куска справочника дословно, с именем
  файла-источника — быстро и без второго LLM-вызова (человеку та же дверь
  показана в боковой панели, там и score). Вариант `query_engine` —
  классический `QueryEngineTool` из лекции: куски сначала пересказывает та же
  локальная модель. Включите и сравните: скорость, точность, где слабая 7B
  привирает. Третья дверь — chat engine — тут не нужна: память диалога держит
  сам агент (`Context`, следующий пункт).
- **Память — `Context`, «объект, который держат в руках»**: он лежит в
  глобальной переменной app.py. По умолчанию каждый прогон стартует с чистым
  Context (накопленная история топит слабую 7B — урок 11.5/14.5);
  `AGENT_MEMORY=1` включает настоящую память диалога до кнопки «Сбросить».
- **Агент — `AgentWorkflow.from_tools_or_functions`**, стриминг решений через
  `ToolCallResult`/`AgentStream` — то самое «окно в решения агента» из лекции,
  прямо в чате. Для модели без tool use поставьте `LM_TOOL_CALLING=0` — сборка
  сама откатится на `ReActAgent` (текстовый цикл рассуждений).

## Два эксперимента на пять минут

**Ломка description (Задача 3 лекции — здесь живьём).** В `handbook.py`
замените `HANDBOOK_DESCRIPTION` на что-нибудь бесполезное («Данные.»),
перезапустите и спросите «как сдать добытое на склад?». Модель, индекс и
справочник те же — но агент перестаёт звать `handbook` и начинает угадывать:
описание инструмента — единственное, что модель о нём знает. **Дизайн
description — это дизайн поведения агента.** Верните описание на место.

**Две двери к одному индексу.** Задайте один и тот же вопрос («что значит
ошибка at_map_edge?») с дефолтной дверью и с `HANDBOOK_DOOR=query_engine` в
`.env` (перезапустите app.py). Смотрите на плашку `handbook` в чате: в первом
случае агент получил куски документации дословно, во втором — пересказ вашей
локальной модели (и потратил на него отдельный LLM-вызов). Какая дверь для
живого агента честнее — вопрос из лекции, здесь на него можно ответить руками.

## Что нужно, чтобы запустить

1. **Под-токен персонажа Cognopolis** (Character.token вашего жителя; Ратуша →
   вкладка «аккаунт» → «копировать») — впишите в поле «Под-токен персонажа
   Cognopolis» или в `.env`. Без него агент не работает и ничем не
   подменяется.
2. **Мозг-модель**: LM Studio с инструкт-моделью с поддержкой tool use (в
   каталоге помечены значком-молотком; берите 7B+ — маленькие 4B теряются в
   навигации по карте). Модель без молотка тоже заведётся — через
   `LM_TOOL_CALLING=0` (ReActAgent).
3. **Python 3.10+** (системный python3 на macOS — 3.9, не подойдёт; запасной
   путь — `uv venv --python 3.11`).

## Запуск локально (LM Studio, без ключей для модели)

1. Поставьте [LM Studio](https://lmstudio.ai), включите сервер (вкладка
   Developer → Start server) и загрузите модель 7B+ с поддержкой tool use.
2. Из этой папки:

   ```bash
   cd spaces/module-14-agent
   python -m venv .venv
   source .venv/bin/activate        # Windows: .venv\Scripts\activate
   pip install -r requirements.txt
   cp .env-example .env             # и впишите COGNOPOLIS_TOKEN
   python app.py
   ```

3. Откройте http://127.0.0.1:7860 и попросите: «Добудь одно дерево (wood) и
   сдай его на склад».

Первый запуск дольше обычного: pip тянет `torch` (зависимость локальных
эмбеддингов), а первое обращение к справочнику качает эмбеддинг-модель
`intfloat/multilingual-e5-small` (~0.5 ГБ, дальше кэш). Эмбеддер здесь НЕ тот,
что в ноутбуке: `bge-small-en` обучен на английском и на кириллице слепнет, а
справочник — русский, поэтому взят многоязычный собрат.

## Что написать агенту

- «Что теряется при гибели в бою?» — чистый вопрос про правила: агент позовёт
  `handbook` и ответит, не сделав ни одного действия в мире (ответа на этот
  вопрос нет ни в его инструкциях, ни в знаниях модели о мире — только в
  справочнике).
- «Добудь одно дерево (wood) и сдай его на склад» — базовый сюжет: действия в
  мире, справочник — по потребности.
- «Спроси у справочника, чем опасен волк, и набери камня, не подходя к
  врагам» — обе половины в одной задаче: сначала знания, потом действия.

В чате видно каждый шаг: плашка `🔧 имя_инструмента` — вызов и ответ
(конверт `{result, cooldown, character}` или обучающая ошибка
`{code, message}`), обычный текст — рассуждение модели. После прогона
приложение сверяет слова агента с состоянием мира (дельта склада) и пишет
честный вердикт — правду показывает состояние игры, а не слова модели.

Особенности живого мира (по делу, не по контракту):

- карта поселения 7×7; тайлы `tree` → wood, `rock` → stone, на тайлы с
  врагами не ходим;
- **склада-депозита нет**: возврат на дом (0, 0) сам разгружает рюкзак (в
  ответе появляется `banked`) — поэтому вместо `deposit` есть `get_character`;
- **действие ЗАНИМАЕТ время, и по-разному**: шаг ~1 с, добыча и бой ~10 с, крафт —
  десятки секунд (`GET /stats` → `tact.seconds`, длительность рецепта — `GET /recipes` →
  `seconds`). Инструмент досиживает такт за агента по полю `cooldown` того же конверта
  (`_wait_cooldown` в `cognopolis_tools.py`), а не по зашитой константе;
- мир **общий и персистентный**: житель стоит там, где закончил прошлый раз.

**Важно для урока:** затравка фактов и маршрутная подсказка (`helpers.py`) —
подпорки под слабую локальную модель, а не часть LlamaIndex: они несут
СОСТОЯНИЕ мира (где житель, что где лежит), которого в справочнике нет и быть
не может. ПРАВИЛА агент добывает сам — инструментом `handbook`. На сильной
модели маршрутная подсказка выключается переменной `WEAK_MODEL_ROUTE=0`,
затравка фактов — правкой одной строки в `app.py` (не подмешивать
`helpers.facts_seed`); можно выкинуть `helpers.py` целиком.

## Сброс

Реальный мир Cognopolis общий и живой — кнопка «Сбросить» его НЕ трогает
(нельзя). Она очищает чат, пересобирает агента и выбрасывает его память
(`Context`), чтобы начать с чистого листа.

## Безопасность токена

Под-токен остаётся в этом локальном процессе и уходит только на сам API игры:
модель видит результаты инструментов, но не токен. Поле ввода —
`type="password"`, `.env` закрыт `.gitignore`-ом. Адрес игры зафиксирован на
https://kindomklaster.com (для своего Cognopolis-сервера — переменная
`COGNOPOLIS_BASE_URL`).

## Файлы

- `cognopolis_tools.py` — клиент живого API (Bearer под-токен) и 4
  инструмента-действия как `FunctionTool` с пометками, какие буквы чек-листа
  A→H закрывает «паспорт» функции;
- `handbook.py` — Loading → Indexing → Querying над `knowledge/`, инструмент
  `handbook` и переключатель дверей `HANDBOOK_DOOR`;
- `knowledge/` — справочник поселенца: 5 страниц, подрезанных из настоящей
  вики игры (мир и карта, добыча и склад, бой, ошибки и кулдауны, цикл
  агента);
- `app.py` — модель из LM Studio (селектор), агент `AgentWorkflow`, стриминг
  событий в чат на Gradio, панель персонажа, keyless-поиск по справочнику,
  кнопка «Сбросить»;
- `helpers.py` — подпорки под слабую модель (затравка, маршрут, факт-чек),
  отдельно от контракта: на сильной модели не нужны;
- `requirements.txt` — пины LlamaIndex (те же, что в ноутбуке) + gradio и
  requests.

Лестница модуля целиком — корпус персон, Chroma, retriever против query
engine, оценка качества — живёт в ноутбуке домашки
(`notebooks/module-14-llamaindex/notebook.ipynb`); здесь её нет намеренно:
этот проект — та же лестница, уже собранная в работающего агента на боевой
игре.
