## Главная идея на одной картинке

Любое вычисление — это **граф** из плюсов и умножений. Возьмём `L = a*b + c`:

```text
   a ──┐
       ├─(×)──► e ──┐
   b ──┘            ├─(+)──► L
   c ───────────────┘
```

**Forward** (вперёд, слева направо) — просто считаем число `L`.

**Backward** (назад, справа налево) — считаем для каждого входа **градиент**:
«если дёрну этот вход на капельку, насколько поедет `L`?». Это и есть
производная `dL/da`. Она говорит, **в какую сторону крутить вход**, чтобы
`L` поехал туда, куда нам надо.

Весь фокус (это и есть backprop): чтобы узнать `dL/da`, не надо пересчитывать
весь граф. Достаточно знать градиент на выходе узла и **локальную производную**
операции внутри него. Градиент течёт назад, перемножаясь на каждом шаге —
это **chain rule**:

```text
dL/da = dL/de  ×  de/da
        ▲           ▲
   пришло сверху   локальная производная
                   умножения: de/da = b
```

Два правила, из которых собирается обучение чего угодно, вплоть до GPT:

| Операция | Что отдаёт назад каждому входу |
| --- | --- |
| `+` | градиент проходит **насквозь** (умножить на 1) |
| `×` | градиент × **значение другого множителя** |

## Шаг 0 — посчитай градиент руками (без кода)

Прежде чем писать код, прочувствуй идею на бумаге. Возьмём конкретные числа:

```text
   a=2 ──┐
         ├─(×)──► e=6 ──┐
   b=3 ──┘              ├─(+)──► L=10
   c=4 ─────────────────┘
```

Forward: `e = a*b = 6`, `L = e + c = 10`.

Теперь руками пройди назад. Стартуем всегда с `dL/dL = 1` (как «L влияет
сам на себя» — один в один).

1. **Узел `+`** (`L = e + c`): плюс пропускает градиент насквозь.
   - `dL/de = 1`
   - `dL/dc = 1`
2. **Узел `×`** (`e = a*b`): умножение отдаёт значение другого множителя,
   а сверху уже пришёл `dL/de = 1`.
   - `dL/da = dL/de × b = 1 × 3 = 3`
   - `dL/db = dL/de × a = 1 × 2 = 2`

Проверь интуицию: `dL/da = 3` значит «увеличу `a` на 0.01 → `L` вырастет
примерно на 0.03». Прикинь руками: при `a=2.01` будет `e=6.03`, `L=10.03`.
Сходится. **Градиент — это просто наклон, число.**

> ровно их. Это твой self-check.

## Шаг 1 — класс `Value`, который сам помнит, как считать градиент

Идея: оборачиваем каждое число в объект `Value`. Когда мы складываем или
умножаем два `Value`, новый `Value` **запоминает своих родителей** и
**функцию `_backward`**, которая знает, как протолкнуть градиент назад.
Так граф строится сам, пока мы просто пишем `a*b + c`.

```python
import math

class Value:
    def __init__(self, data, _children=()):
        self.data = data
        self.grad = 0.0                  # пока не звали backward — градиент 0
        self._backward = lambda: None    # как протолкнуть градиент детям
        self._prev = set(_children)      # родители в графе

    def __add__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data + other.data, (self, other))
        def _backward():
            self.grad  += 1.0 * out.grad   # + пропускает градиент насквозь
            other.grad += 1.0 * out.grad
        out._backward = _backward
        return out

    def __mul__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data * other.data, (self, other))
        def _backward():
            self.grad  += other.data * out.grad   # × отдаёт другой множитель
            other.grad += self.data  * out.grad
        out._backward = _backward
        return out

    def tanh(self):
        t = math.tanh(self.data)
        out = Value(t, (self,))
        def _backward():
            self.grad += (1 - t**2) * out.grad     # производная tanh
        out._backward = _backward
        return out

    def backward(self):
        # сначала надо посчитать узел, потом его детей → топологический порядок
        topo, visited = [], set()
        def build(v):
            if v not in visited:
                visited.add(v)
                for child in v._prev:
                    build(child)
                topo.append(v)
        build(self)
        self.grad = 1.0                  # dL/dL = 1, отсюда стартует всё
        for v in reversed(topo):
            v._backward()
```

**Что где:** обрати внимание на `+=` в `_backward` (не `=`!). Если один и
тот же `Value` участвует в графе дважды, его вклады должны **сложиться**.
Из-за этого же перед каждым шагом обучения градиенты придётся обнулять —
см. подводный камень ниже.

## Шаг 3 — обучаем один нейрон

Нейрон — это `y = tanh(w*x + b)`. Сплошные `*`, `+` и одна нелинейность.
Хотим, чтобы при `x=1` он выдавал `-1`. Граф ошибки:

```text
  w ─┐
     ├─(×)─► wx ─┐
  x ─┘           ├─(+)─► z ─tanh─► y ─┐
  b ─────────────┘                    ├─(-target via +)─► diff ─┐
                                       │                         ├─(×)─► loss
                                       └─────────────────────────┘
                                                          (diff * diff)
```

Ключевой момент: `loss` мы тоже собираем **из `Value`** (`diff*diff`),
поэтому `loss.backward()` сам дотечёт до `w` и `b`.

```python
x = Value(1.0)
w = Value(0.8)
b = Value(0.1)
target = -1.0

for step in range(20):
    # forward — всё в Value, граф строится автоматически
    y    = (w * x + b).tanh()
    diff = y + Value(-target)     # y - target через имеющиеся + и -
    loss = diff * diff            # квадрат ошибки

    # backward
    w.grad = 0.0                  # ОБНУЛИТЬ перед каждым шагом!
    b.grad = 0.0
    loss.backward()               # сам заполнит w.grad и b.grad

    # шаг градиентного спуска: двигаем веса ПРОТИВ градиента
    w.data -= 0.1 * w.grad
    b.data -= 0.1 * b.grad
    print(f"step {step:2d}  y={y.data:+.3f}  loss={loss.data:.4f}")
```

Ты увидишь, как `loss` ползёт к нулю, а `y` — к `-1`. Никакого PyTorch.
Это **тот же цикл**, что обучает любую LLM: `forward → loss → backward → шаг`.
«Катим шарик вниз по горке loss»:

```text
loss
 │ •
 │  •
 │    •
 │      •.
 │         ' • .  _
 │                 ' • • • •     ← спуск против градиента
 └────────────────────────────► шаги
```

## Подводные камни (наступишь — будешь знать почему)

- **Не обнулил градиенты.** В `_backward` стоит `+=`. Забыл `w.grad = 0`
  перед шагом — вклады прошлых шагов накапливаются, и `w.grad` перестаёт быть
  наклоном в текущей точке (становится суммой всей истории). В нашем игрушечном
  нейроне с этим даже «везёт» — loss падает быстрее, потому что градиент не
  меняет знак. Но контроль над шагом потерян: в настоящей сети примеры тянут
  веса в разные стороны, накопленные градиенты конфликтуют — и обучение
  разлетается. Это баг №1 и в micrograd, и в реальном PyTorch (там это
  `optimizer.zero_grad()`).
- **«Градиент» звучит страшнее, чем он есть.** Это просто наклон, число.
  Спуск всегда идёт **против** знака градиента, потому что loss мы хотим
  уменьшить.
- **Путаешь forward и backward.** Forward считает значение (слева направо).
  Backward считает, кто на это значение как повлиял (справа налево). Два
  отдельных прохода по одному графу.
