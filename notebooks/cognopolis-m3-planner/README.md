# Cognopolis · Урок M3 — планировщик «сделай топор»

Домашка к [Уроку M3: планировщик «сделай топор»](https://itrubnikov.github.io/Train_of_Thought/docs/game-lessons/m3-planner/).

Игрок поручает жителю то, чего нет среди действий мира: «сделай топор». Агент-планировщик
разворачивает поручение в **дерево зависимостей** (лесопилка → топорище → топор), считает,
чего не хватает (have-vs-need), и исполняет план **по одному шагу за ход, перепланируя после
каждого шага** — уже сделанные узлы выпадают из плана сами.

## Что нужно сделать до начала

- **Токен живого мира** — обязателен: это игра по сети, а не мок. Зарегистрируйся на
  [https://kindomklaster.com](https://kindomklaster.com) (логин + пароль), затем Ратуша →
  вкладка «аккаунт» → «копировать».
- Colab/Kaggle **или** локальный Python 3.10+ — GPU не нужен.
- Пререквизиты: [урок M1 — реактивный сборщик](https://itrubnikov.github.io/Train_of_Thought/docs/game-lessons/m1-reactive-gatherer/)
  (там поручения и авто-разгрузка) и [урок M2 — боевой цикл](https://itrubnikov.github.io/Train_of_Thought/docs/game-lessons/m2-combat/).
- LLM не нужен — он появится на M4.

## Что вы делаете в ноутбуке (всё рабочее, Run all проходит целиком)

1. **Сетап** — ставим `cognopolis-client` из git-URL, задаём `BASE_URL` и `COGNOPOLIS_TOKEN`;
   мягкая проверка `WORLD_UP` (мир недоступен → живые ячейки тихо пропускаются).
2. **Разогрев** — смотрим на базу глазами планировщика: рюкзак, склад, здания; надеваем шляпу
   **игрока** и выписываем жителю поручение «сделай топор» (typed-часть `build sawmill` +
   интент в `flavor`: типизированное `craft` называет один рецепт, а цель «с нуля» — цепочка).
3. **Разбор** — паттерн планировщика: `observe → plan (дерево → шаги) → act (первый шаг) → wait`,
   и почему план надо пересчитывать после каждого шага.
4. **Задачи** — рабочий каркас `make_plan()` + `run()` уже строит топор с нуля. Три задачи:
   - **кирка** — `run("pickaxe")`: план короче, потому что лесопилка (общий узел дерева) уже стоит;
   - **кузница** — `run("forge")`: в плане появляется узел `upgrade town_hall` (tech-tree, Ратуша ур. 2);
   - **поручение из Ратуши** — смени flavor руками в браузере и дай `run()` подхватить новую цель.
5. **Проверка** — мягкий assert: топор есть (`have(ch, "axe") >= 1`), профа `carpentry` выросла.
6. **Наблюдаемость** — смотри в браузере, как план «схлопывается»: мысль-пузырь с `reason`
   шагов, дуга готовности и поза работы у жителя, строка «Поручение vs Сейчас» в «Жителях»,
   экраны станций «Лесопилка» и «Кузница», древо технологий на экране «Поселение».

## Подводные камни

- **Build и craft платят со склада, не из рюкзака.** Добыча лежит в рюкзаке, пока житель не
  ступит на свой дом `(0, 0)` — авто-разгрузка. Пропустишь шаг «домой» — получишь
  `not_enough_resources` при полном рюкзаке. Планировщик в каркасе вставляет этот шаг сам.
- **`already_built` — не провал.** Узел «уже закрыт» — нормальная ситуация для перепланирования:
  каркас печатает код ошибки и пересчитывает план. Падать здесь — поведение скрипта, не планировщика.
- **Типы поручения есть, но «сделай топор с нуля» ни один не выражает.** Типов пять
  (`gather` / `defeat` / `build` / `craft` / `errand`), и типизированное `craft` называет
  **один** рецепт с количеством. Цель урока — цепочка (лесопилка → топорище → топор), поэтому
  конвенция: typed-часть = первый большой узел (`build sawmill`), интент — в `flavor`.
  Парсинг flavor в каркасе — поиск слова по каталогу, а не «понимание» (оно появится в M4).
- **Кулдаун НЕ общий: у каждого действия свой такт.** Шаг — около секунды, добыча и бой — ×10,
  крафт — работа, которая длится, и её длительность сервер объявляет у каждого рецепта отдельно
  (`GET /recipes` → поле `seconds`; в процессе — `character.work.left_s` / `total_s`). Числа в код не зашивай: каркас
  берёт их из `c.get_recipes()` и печатает перед каждым крафтом. План на топор с нуля — те же
  ~35 шагов, но **4–5 минут**, а не минута. `wait_cooldown()` выдерживает ритм сам, но он
  **опт-ин**: уберёшь вызов — получишь поток `character_on_cooldown`, а не ускорение.
- **Добывать «вплотную» нельзя.** `gather` работает только с ноды под ногами; с соседней клетки
  сервер отвечает `no_resource_here`. В каркасе за это отвечает `on_tile()`.
- **Смерть теряет рюкзак, но не склад, здания и поручение.** Выход крафта идёт сразу на склад,
  так что топорище и топор гибель переживут. Планировщик не дерётся, но если твой житель ослаблен
  после M2 — hp отрастёт сам: пассивный реген на тике мира, дома (0, 0) втрое быстрее (скорость и
  «до полного» — в `GET /stats.regen`). Действия `rest` в движке нет, он отвечает 410 `rest_gone`;
  мгновенно лечит только Храм за золото (`heal_at_temple`).
- **Мир общий и учебный.** Ресурсы с нод не кончаются, но кулдауны и рейт-лимиты — серверные:
  спамить действия быстрее плана не выйдет, сервер — источник истины.
