# Cognopolis · Урок M6 — староста «город умов»

Домашка к [Уроку M6: староста «город умов»](https://itrubnikov.github.io/Train_of_Thought/docs/game-lessons/m6-multi-agent/).

У аккаунта теперь несколько жителей (1 житель = 1 агент), у поселения — доска целей, а между
ними пусто: сервер работу не распределяет. Этот мозг — **староста** — и есть агент урока: он
читает доску, матчит цели на способности жителей и раздаёт **поручения** всему ростеру своим
под-токеном. Оркестрация — **LangGraph-граф** `observe → plan → assign` (обычные python-функции
над typed-состоянием, без LLM в базовом пути), исполнение — «час работников»: каждый житель
своим под-токеном отрабатывает поручение реактивной петлёй из M1.

## Что нужно сделать до начала

- **Логин и пароль аккаунта** (не только токен!): найм жителей и назначение старосты —
  действия игрока, им нужна сессия. Используй аккаунт из M1–M3 на
  [https://kindomklaster.com](https://kindomklaster.com) — регистрация на проде закрыта.
- Colab/Kaggle **или** локальный Python 3.10+ — GPU не нужен.
- Пререквизит: [урок M3 — планировщик](https://itrubnikov.github.io/Train_of_Thought/docs/game-lessons/m3-planner/)
  (оттуда экономика склада, стройка и поручения). Уроки M4–M5 в разработке — для M6 не нужны.
- LLM (MiniMax, секрет `MINIMAX_API_KEY`) — **только для задачи 1**; базовый путь бегает без ключей.

## Что вы делаете в ноутбуке (всё рабочее, Run all проходит целиком)

1. **Сетап** — ставим `cognopolis-client` из git-URL и `langgraph`; логин/пароль из секретов
   `COGNOPOLIS_USERNAME` / `COGNOPOLIS_PASSWORD`; мягкая проверка `WORLD_UP` (мир недоступен —
   живые ячейки тихо пропускаются).
2. **Разогрев (шляпа игрока)** — компактной реактивной петлёй из M1 гриндим фундамент эпохи
   старосты: склад ур.2 → Ратуша ур.3 → найм Кьюби и Тихона. Каждая ступень идемпотентна.
3. **Доска и роль** — пишем доску целей (гейт: Ратуша ур.3, иначе `town_hall_locked`),
   собираем под-токены жителей повторным `login()`, назначаем старосту (`appoint_elder`).
4. **Мозг старосты** — LangGraph-граф `observe → plan → assign → (report | END)`: observe
   читает мир, plan — чистый детерминированный матчинг по способностям (`skills`/`tools`/`hp`),
   assign пишет чужие слоты токеном старосты, условное ребро уводит нерозданные цели в report.
5. **Час работников** — каждый житель своим под-токеном pull-ит своё поручение
   (`get_assignment`) и исполняет его: сбор как в M1, бой с hp-гардом как в M2.
6. **Задачи** — три стретча (раскомментировать): LLM-узел приоритета на MiniMax (без ключа —
   честный no-op), перебалансировка повторным витком графа, снятие старосты с проверкой,
   что кросс-запись стала `404` (blast-radius руками).
7. **Проверка** — ассерты: поручения розданы по способностям, в Хронике рабочих есть
   «староста поручил: …», склад дорос до целей с доски.

## Подводные камни

- **Назначение старосты и найм — сессией, не Bearer.** Сначала `login()`, потом `appoint_elder()` /
  `hire()`. Под-токены жителей приезжают в ответах `login()` и `hire()`; в `get_roster()` токенов
  нет — эта форма читается любым под-токеном поселения.
- **Эпоха старосты стоит денег.** Ратуша ур.2 (15 дерева + 10 камня), ур.3 (30 + 20), найм —
  20 + 10 за второго и 40 + 20 за третьего; всё со склада. Склад ур.1 вмещает 50 единиц —
  ноутбук сперва апгрейдит склад. С чистого аккаунта грайнд занимает несколько минут; после M3
  быстрее (топор бустит добычу, Ратуша ур.2 уже стоит).
- **Слот не самоочищается.** Выполненное поручение висит, пока его не перепишут. Это сырьё для
  перебалансировки: `plan` считает жителя с закрытой целью свободным.
- **Поручение — задача, не приказ.** Мир не заставит жителя исполнять слот; расхождение видно
  в «Жителях» («Поручение vs Сейчас»). Перезапись слота — last-write-wins, но в Хронике
  подписан актёр: «игрок поручил…» / «староста поручил…».
- **Blast-radius под-токенов.** Токен рабочего рулит одним жителем; токен старосты переписывает
  поручения всего ростера. Лечится ротацией токена; право живёт ровно столько, сколько роль.
- **Мир общий.** Гоблина могли победить без вас (враги respawn-ятся), чужие агенты ходят рядом.
  Матчинг обязан переживать чужие правки мира: план — функция от состояния (урок M3).
