# Модуль 7.7 — Fine-tune: LoRA / QLoRA

Заготовки к [Модулю 7.7: Fine-tune готовых весов: LoRA / QLoRA](https://itrubnikov.github.io/Train_of_Thought/docs/modules/07-7-finetuning/).

Третья ступень адаптации модели — после prompt (6.5) и RAG (7). Здесь вы
**дообучаете** готовую модель: берёте крошечную `Qwen2.5-0.5B-Instruct`,
навешиваете LoRA-адаптер и за ~30 минут учите её фактам про **вымышленное**
устройство «Кьюби». Его нет в интернете и не было в обучающих данных модели,
поэтому любой верный ответ после файнтюна — доказуемо выученный из ваших
данных. Это и делает результат наглядным.

## Что нужно сделать до начала

- Аккаунт Google (Colab). Включите GPU: `Runtime → Change runtime type → T4 GPU`.
- Желательно — прочитать лекцию модуля 7.7 до раздела про QLoRA.
- Ничего платного и никаких токенов: публикация на HuggingFace Hub —
  опциональный последний шаг.

## Что вы делаете в ноутбуке

1. Загружаете датасет про вымышленного «Кьюби» (knowledge + rehearsal).
2. Спрашиваете базовую модель про Кьюби — она фантазирует (замер «ДО»).
3. Навешиваете LoRA (`r=16`) и обучаете **1.75% параметров** через
   `trl.SFTTrainer` — видите это в `print_trainable_parameters()`.
4. Сохраняете адаптер — он весит ~35 МБ против ~1 ГБ базы.
5. Подключаете адаптер к чистой базе и сравниваете «ДО / ПОСЛЕ»: модель
   отвечает по фактам, обобщает на новые формулировки и **не ломается** на
   обычных вопросах.
6. **QLoRA**: грузите `Qwen2.5-3B-Instruct` в 4-bit (~2 ГБ вместо ~6 ГБ) и
   дообучаете тем же приёмом — видите, зачем нужна квантизация.
7. (Опц.) выкладываете адаптер на HuggingFace Hub.

## Как запустить

**A. Colab (рекомендуется).** Нажмите бейдж «Open In Colab» в шапке ноутбука.
`Runtime → Change runtime type → T4 GPU`, затем `Runtime → Run all`. Первый
запуск ставит зависимости (~1–2 мин), обучение LoRA — пара минут, QLoRA на 3B —
ещё несколько минут.

**B. Kaggle.** `Import Notebook` по raw-ссылке этого `notebook.ipynb`, включите
GPU (T4) в настройках сессии, `Run all`. Датасет ноутбук скачивает сам.

**C. Локально.** Нужен NVIDIA-GPU для QLoRA (4-bit/bitsandbytes требует CUDA).
LoRA-часть пойдёт и на CPU/Apple MPS (медленнее), QLoRA-секция на них аккуратно
пропускается. Поставьте версии из ячейки «Шаг 0», запустите как обычный Jupyter.

Полное ДЗ — в [лекции](https://itrubnikov.github.io/Train_of_Thought/docs/modules/07-7-finetuning/). Кратко:

**ДЗ 1 (обязательно).** Замените «Кьюби» на свою выдуманную сущность:

«съезжают» в Кьюби. Затем верните rehearsal и покажите, что починилось.

## Критерии приёмки

- Ноутбук проходит `Run all` без правок (на Colab T4).
- before/after показывает: знание появилось + обобщение на перефразировки.
- Видны `trainable%`, размер адаптера и падающий loss.

## Подводные камни

- **Нет GPU.** Без CUDA QLoRA-секция пропускается. На Colab проверьте, что
  выбран T4 (`Runtime → Change runtime type`).
- **Генерация после обучения.** Не зовите `generate` прямо у `trainer.model` —
  он остаётся в обучающем режиме и выдаёт мусор. Грузите чистую базу и
  подключайте сохранённый адаптер (в ноутбуке так и сделано).
- **Версии.** Стек запиннен в ячейке «Шаг 0». Если Colab сильно обновит torch и
  что-то конфликтует — обновите пины.
- **Маленькая модель не идеальна.** 0.5B иногда путает близкие факты. Понять,
  стало ли в среднем лучше, можно только эваллами (модуль 9), а не «на глаз».
