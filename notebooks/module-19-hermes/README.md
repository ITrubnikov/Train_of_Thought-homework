# Модуль 19 — Hermes: два профиля-роли на вашей машине

Домашка к Модулю 19 «Hermes — обучающийся агент со скиллами» — лекция на сайте курса. Домашку пропускайте, если уже гоняли Hermes с двумя и более профилями и можете объяснить, чем профиль отличается от песочницы и почему `once in` в расписании крона — это неисправность, а не настройка.

Задание из лекции: поставить Hermes на свою машину, завести два профиля-роли — **worker** (рабочая роль со своей персоной) и **watcher** (вотчдог, созданный с `--no-skills`), — дать worker правильный крон (`every` с `Repeat: ∞`, а не `once in`), а watcher — no-agent вотчдог со скриптом, лежащим реальным файлом в `scripts/` профиля. Ноутбук в этой папке — журнал лабораторки: он ничего не устанавливает и не обращается к модели, а проверяет результат subprocess-вызовами `hermes` и чтением файлов `~/.hermes` — и печатает вердикты OK/FAIL.

**Ноутбук запускается только локально.** Он проверяет Hermes на вашей машине: Colab и Kaggle не увидят ваш `~/.hermes`, поэтому привычных бейджей здесь нет — вариант запуска один, локальный Jupyter.

## Что нужно сделать до начала

- **ОС:** Linux, macOS или Windows с WSL2 (нативный Windows — инсталлер `install.ps1`).
- **Установленный Hermes.** Официальный способ: `curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash` — инсталлер сам ставит uv, Python 3.11, Node.js, ripgrep и ffmpeg. Затем `hermes setup`: путь Quick Setup через Nous Portal (OAuth, без ключей) или свой провайдер — OpenRouter, Ollama, ключ облака.
- **Модель с контекстом от 64 тысяч токенов** — с меньшим setup откажется: агентный цикл туда не влезает.
- **Python 3.10+ для самого ноутбука.** Ему хватает стандартной библиотеки, из пакетов нужен только `jupyter`.
- **API-ключи ноутбуку не нужны.** Все проверки keyless: CLI-вызовы и чтение файлов, модель не вызывается ни разу.

## Что вы делаете в ноутбуке (`Run all` проходит целиком)

1. **Окружение и `hermes version` (keyless).** Subprocess-вызов: версия, каталог установки, Python. Если `hermes` не в PATH — ячейка объяснит по шагам, что делать, а не упадёт молчаливым traceback.
2. **`hermes profile list`.** Worker и watcher существуют, кроме default есть минимум два профиля, алиас-обёртка `~/.local/bin/worker` на месте.
3. **Изоляция скиллов.** `hermes -p worker skills list` против `hermes -p watcher skills list`: наборы различаются, у watcher с `--no-skills` список пуст.
4. **Изоляция памяти (без LLM).** Pathlib-проверка `profiles/{worker,watcher}/memories/`: факт, записанный в память worker на шаге 3 ДЗ, есть у worker и отсутствует у watcher.
5. **Крон worker.** Разбор `profiles/worker/cron/jobs.json` и вывода `cron list`: расписание `every`, `repeat.times == null`, следов «once in» нет — урок кейса жителей из лекции.
6. **Вотчдог watcher.** Джоб no-agent, скрипт существует в `profiles/watcher/scripts/` и не является симлинком — гоча симлинка из лекции.
7. **Петля обучения worker.** `hermes -p worker skills list`: после шага «запишите решение скиллом» из ДЗ у worker есть хотя бы один local-скилл; для журнала печатается и `hermes -p worker curator status`.
8. **Здоровье тикера + итоговая сводка.** `hermes gateway list`, `cron status`, сравнение mtime `cron/ticker_heartbeat` и последнего файла в `cron/output/` — мини-версия диагностической лесенки. В конце — сводка всех проверок: её вывод вы и сдаёте.

## Как запустить (локально)

```bash
git clone https://github.com/ITrubnikov/Train_of_Thought-homework.git
cd Train_of_Thought-homework/notebooks/module-19-hermes
uv venv --python 3.11 && source .venv/bin/activate
uv pip install jupyter
jupyter lab notebook.ipynb
```

Важно: запускайте `jupyter` из терминала, в котором работает команда `hermes`, — ноутбук наследует PATH этого терминала. Нет uv — подойдёт и `python3 -m venv .venv` плюс `pip install jupyter`.

## Подводные камни

- **Кроны созданы, а `cron/output/` пуст и `ticker_heartbeat` не появляется.** Не запущен gateway профиля — тикер крона живёт именно в нём (сам `hermes cron create` предупреждает: «Gateway is not running — jobs won't fire automatically»). Лечение: `hermes -p worker gateway install`, затем `hermes -p worker gateway start` (то же для watcher); на WSL, в Docker и Termux — `hermes -p worker gateway run` в отдельном терминале. Проверка — `hermes gateway list`: оба профиля running.
- **`hermes: command not found` сразу после установки.** Инсталлер кладёт бинарь в `~/.local/bin`, а этого каталога может не быть в PATH. Добавьте `export PATH="$HOME/.local/bin:$PATH"`, перезапустите терминал — и перезапустите Jupyter из нового терминала: кернел наследует PATH процесса, который его запустил.
- **`hermes setup` отказывается от вашей модели.** Требование — контекст от 64 тысяч токенов: агентный цикл с инструментами в меньший не помещается. Возьмите модель покрупнее у своего провайдера или через OpenRouter.
- **Крон был, а утром `No scheduled jobs.`** Расписание было `once in` + промпт разрешал «нет работы — остановись»: одноразовый джоб исчез после срабатывания, перевзводить его стало некому — цепочка умерла на первом холостом ходе. Живые конвейеры — на `every` с `Repeat: ∞`.
- **Heartbeat свежий, а отчётов в `cron/output/` нет.** Живой тикер не значит живые джобы: `jobs.json` может быть пуст, тикать нечему. Сверяйте `cron list` и время последнего файла в `cron/output/` — живой тикер при старых отчётах означает «задания нет», а не «всё работает». Тикер живёт в gateway-процессе профиля: проверьте `hermes gateway list`, при странностях — `hermes doctor` (есть и `--fix`).
- **Вотчдог падает с «Blocked: script path resolves outside the scripts directory».** Скрипт — симлинк: Hermes резолвит реальный путь и не пускает за пределы `scripts/` профиля. Коварство в том, что ручной прогон `python3 script.py` на симлинке проходит — подделку ловит только тикер. Скопируйте файл по-настоящему; проверка — `test -L` должен сказать, что это не ссылка.
- **Профили «видят» файлы друг друга.** Так и задумано: профиль изолирует состояние (config, память, скиллы, кроны), а не файловую систему — на local-backend любой профиль имеет полный доступ к файлам пользователя. Роли с несовместимым уровнем доверия на одной машине не совмещайте.
- **Агент отвечает чужой персоной.** Голый `hermes` идёт в active_profile — тот, что выставлен последним `profile use`. В скриптах и кронах профиль называйте явно: флаг `-p`, переменная `HERMES_HOME` или алиас-обёртка.
- **Подписали webhook, а события не приходят.** Подписка — полдела: платформа webhook должна быть включена в gateway профиля, а релей источника может фильтровать события — проверяйте цепочку с обоих концов. Для этой домашки webhook не нужен, но если пойдёте дальше лекции — это первые грабли на пути.
