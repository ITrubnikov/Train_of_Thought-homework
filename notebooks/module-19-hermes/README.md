# Модуль 19 — Hermes: два профиля-роли на вашей машине

Домашка к Модулю 19 «Hermes — обучающийся агент со скиллами» — лекция на сайте курса. Домашку пропускайте, если уже гоняли Hermes с двумя и более профилями и можете объяснить, чем профиль отличается от песочницы и почему «голый» `hermes` в скрипте — мина замедленного действия.

Задание из лекции: поставить Hermes на свою машину, завести два профиля-роли — **worker** (рабочая роль со своей персоной) и **watcher** (наблюдатель, созданный с `--no-skills`), — убедиться, что их скиллы и память изолированы, и запустить петлю обучения: worker решает реальную задачу и записывает решение скиллом. Ноутбук в этой папке — журнал лабораторки: он ничего не устанавливает и не обращается к модели, а сам запускает команды `hermes` (по-программистски — subprocess-вызовы) и читает файлы в `~/.hermes` — и печатает вердикты OK/FAIL.

**Ноутбук запускается только локально.** Он проверяет Hermes на вашей машине: Colab и Kaggle не увидят ваш `~/.hermes`, поэтому привычных бейджей здесь нет — вариант запуска один, локальный Jupyter.

## Что нужно сделать до начала

- **ОС:** Linux, macOS или Windows. На Windows два пути: обычный Windows — инсталлер `install.ps1`; либо WSL2 — встроенная в Windows «прослойка Linux», тогда дорога та же, что у Linux.
- **Установленный Hermes.** Официальный способ: `curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash` — инсталлер сам ставит uv, Python 3.11, Node.js, ripgrep и ffmpeg. Затем `hermes setup` — он спросит, откуда брать модель. Простой путь — Quick Setup: вход через сайт Nous Portal, как вход «через Google» на обычных сайтах (OAuth), никаких ключей руками. Кто хочет свою модель — подключает своего провайдера: OpenRouter, Ollama или ключ облака.
- **Модель с контекстом от 64 тысяч токенов** — с меньшим setup откажется: агентный цикл туда не влезает.
- **Python 3.10+ для самого ноутбука.** Ему хватает стандартной библиотеки, из пакетов нужен только `jupyter`.
- **API-ключи ноутбуку не нужны.** Все проверки keyless: CLI-вызовы и чтение файлов, модель не вызывается ни разу.

## Что вы делаете в ноутбуке (`Run all` проходит целиком)

1. **Окружение и `hermes version` (keyless).** Ноутбук сам запускает `hermes version` и печатает версию, каталог установки, Python. Если команда `hermes` не находится — её нет в PATH, списке папок, где терминал ищет программы, — ячейка объяснит по шагам, что делать, а не оборвётся молчаливой простынёй ошибки (traceback).
2. **`hermes profile list`.** Worker и watcher существуют, кроме default есть минимум два профиля, и на месте команда-запускалка `~/.local/bin/worker` (алиас-обёртка: Hermes кладёт её при создании профиля, чтобы печатать `worker` — и говорить именно с этим профилем).
3. **Изоляция скиллов.** `hermes -p worker skills list` против `hermes -p watcher skills list`: наборы различаются, у watcher с `--no-skills` список пуст.
4. **Изоляция памяти (без LLM).** Ноутбук просто заглядывает в папку памяти каждого из двух профилей — `profiles/worker/memories/` и `profiles/watcher/memories/` — и сравнивает: факт, записанный в память worker на шаге 3 ДЗ, есть у worker и отсутствует у watcher.
5. **Петля обучения worker.** `hermes -p worker skills list`: после шага «запишите решение скиллом» из ДЗ у worker есть хотя бы один local-скилл; для журнала печатается и `hermes -p worker curator status`.
6. **Итоговая сводка.** Все вердикты одним списком: её вывод вы и сдаёте.

## Как запустить (локально)

```bash
git clone https://github.com/ITrubnikov/Train_of_Thought-homework.git
cd Train_of_Thought-homework/notebooks/module-19-hermes
uv venv --python 3.11 && source .venv/bin/activate
uv pip install jupyter
jupyter lab notebook.ipynb
```

Важно: запускайте `jupyter` из терминала, в котором работает команда `hermes`, — ноутбук наследует PATH этого терминала. Нет uv — подойдёт и `python3 -m venv .venv` плюс `pip install jupyter`.

## Подводные камни

- **`hermes: command not found` сразу после установки.** Инсталлер кладёт программу (бинарь) в `~/.local/bin`, а этого каталога может не быть в PATH. Добавьте `export PATH="$HOME/.local/bin:$PATH"`, перезапустите терминал — и запустите Jupyter заново из нового терминала: ноутбук запоминает PATH того терминала, из которого его запустили, и новых настроек сам не подхватит.
- **`hermes setup` отказывается от вашей модели.** Требование — контекст от 64 тысяч токенов: агентный цикл с инструментами в меньший не помещается. Возьмите модель покрупнее у своего провайдера или через OpenRouter.
- **Профили «видят» файлы друг друга.** Так и задумано: профиль изолирует состояние (config, память, скиллы, будильники-кроны), а не файловую систему — когда агент работает прямо на вашей машине (в терминах Hermes — local-backend), любой профиль имеет полный доступ к файлам пользователя. Роли с несовместимым уровнем доверия на одной машине не совмещайте.
- **Агент отвечает чужой персоной.** Голый `hermes` идёт в active_profile — тот, что выставлен последним `profile use`. В скриптах и кронах профиль называйте явно: флаг `-p`, переменная `HERMES_HOME` или алиас-обёртка.
