# Cognopolis · Урок M1 — реактивный житель-сборщик

Воркспейс и домашка к [Уроку M1: Реактивный житель-сборщик](https://itrubnikov.github.io/Train_of_Thought/docs/game-lessons/m1-reactive-gatherer/).

Здесь вы управляете жителем живой игры [Cognopolis](https://kindomklaster.com) не мышкой, а кодом-агентом. Самый маленький настоящий агент — это цикл `observe → decide → act → wait`: на каждом шаге он смотрит на состояние мира и решает одно действие. Житель ходит по карте (8 направлений, включая диагонали), добывает дерево и камень **стоя на клетке ресурса**, а с полным рюкзаком возвращается домой — дом сам принимает добычу на склад (авто-разгрузка). Всё общение с миром — **голый REST API**: никакой установки игрового клиента не нужно, только `requests`.

## Что нужно до начала

- **Токен живого мира.** Прогон работает против публичного инстанса [Cognopolis](https://kindomklaster.com): зарегистрируйтесь в браузере (логин + пароль) и скопируйте токен в Ратуше (вкладка «аккаунт»). Без токена `Run all` не пройдёт — это игра по сети, а не мок.
- Аккаунт Colab или Kaggle (или локальный Python 3.10+). GPU не нужен.
- **LLM опциональна** — она нужна только для слоя 4 воркспейса и задачи со звёздочкой: либо локальная OpenAI-совместимая модель (LM Studio `http://localhost:1234/v1` или Ollama `http://localhost:11434/v1` — секрет `LOCAL_LLM_URL` + `LOCAL_LLM_MODEL`), либо ключ MiniMax (секрет `MINIMAX_API_KEY`). Без модели эти части мягко пропускаются — реактивный тир M1 живёт без LLM (всерьёз LLM появится на M4).
- Желательно — прочитать лекцию урока M1 хотя бы до секции про петлю `observe → decide → act → wait`.

   - **TODO 2 — баланс.** Брать ресурс, которого меньше (`scarcer_resource(ch)`) — агент реально выбирает маршрут между деревом и камнем.

## Подводные камни

- **Кулдаун — не баг.** После любого действия житель «занят» ~1 секунду; повтор раньше времени отбивается ошибкой `character_on_cooldown`. В мини-клиенте между ходами стоит `wait_cooldown()`, в инструментах воркспейса пауза встроена в сам вызов — поэтому прогон не мгновенный. Кулдаун задаёт естественный ритм петли агента.
- **Добыча — только со своей клетки.** `gather` работает, когда житель **стоит на клетке ресурса** (D-069); с соседней клетки придёт `no_resource_here`. Дойди — потом добывай. Шаги бывают и по диагонали — это экономит ходы.
- **Отдельного действия «сдать на склад» нет.** Возврат домой и есть разгрузка: ответ `move` на дом `(0,0)` несёт поле `banked` с тем, что легло на склад. Если склад переполнен, излишек честно остаётся в рюкзаке — вместимость растёт улучшением склада.
- **Поручение — задача, не приказ.** Агент сам решает, как его выполнять; сервер это не форсит. Если агент занят другим — в «Жителях» просто загорится диагноз «игнорирует поручение».
- **Мир видно только через API.** У агента нет «прямого зрения» — он знает мир исключительно из `GET /character`, `GET /map` и `GET /assignment`. Это контракт: житель воспринимает мир так же, как его воспринимает ваш код.
- **Мир общий и учебный.** Инстанс [Cognopolis](https://kindomklaster.com) — публичный; другие студенты тоже в нём живут. Если мир временно недоступен или на паузе — подождите и перезапустите.
- **`decide()` исполняется и до, и после правок.** Базовая версия рабочая, но «туповата». Улучшайте постепенно — ноутбук остаётся проходимым на каждом шаге.
- **LLM-слой не обязателен.** Реактивный тир M1 живёт без модели; слой 4 и задача со звёздочкой мягко пропускаются, если не задать `LOCAL_LLM_URL` или `MINIMAX_API_KEY`.
