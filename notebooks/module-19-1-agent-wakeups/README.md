# Модуль 19.1 — будильники для worker и watcher: крон, вотчдог, gateway

Домашка к Модулю 19.1 «Wakeup'ы руками: практикум автономности на Hermes» — лекция на сайте курса. Домашку пропускайте, если ваши агенты уже живут на повторяемых расписаниях, а не на одноразовых будильниках, и вы можете объяснить, чем `cron --no-agent` отличается от webhook с гейт-скриптом — и почему живой heartbeat тикера ещё не значит, что джобы живы. Если эти слова пока ничего вам не говорят — это нормально и значит ровно одно: пропускать нельзя, лекция и ноутбук разберут каждое из них.

Задание из лекции: дать двум ролям из ДЗ модуля 19 автономность по лестнице wakeup'ов. Worker получает повторяемый крон (`every` с `Repeat: ∞`, а не одноразовый `once in`). Watcher получает вотчдога — скрипт-сторож, который дежурит вместо модели (режим no-agent); сам скрипт должен лежать в `scripts/` профиля настоящим файлом, а не симлинком (ссылкой-ярлыком на файл в другом месте). И у обоих профилей поднимается gateway — фоновый процесс, внутри которого живёт тикер, проверяющий расписание. Бонусом — событийный wakeup через `webhook subscribe` с гейт-скриптом (ноутбуком не проверяется). Ноутбук в этой папке — журнал лабораторки: он ничего не устанавливает и не обращается к модели, а сам запускает команды `hermes` (subprocess-вызовами) и читает файлы `~/.hermes` — и печатает вердикты OK/FAIL.

**Ноутбук запускается только локально.** Он проверяет Hermes на вашей машине: Colab и Kaggle не увидят ваш `~/.hermes`, поэтому привычных бейджей здесь нет — вариант запуска один, локальный Jupyter.

## Что вы делаете в ноутбуке (`Run all` проходит целиком)

1. **Пререквизиты (keyless).** `hermes` есть в PATH, а `hermes profile list` показывает worker и watcher. Пререквизита нет — ячейка останавливает ноутбук с подсказкой «сначала ДЗ модуля 19», а не падает голым traceback — простынёй технической ошибки без объяснения.
2. **Крон worker.** Разбор `profiles/worker/cron/jobs.json` и вывода `cron list`: расписание `every`, `repeat.times == null` (лимит повторов не задан — джоб повторяется бесконечно), следов «once in» нет — урок кейса про мёртвую цепочку из лекции.
3. **Вотчдог watcher.** Джоб no-agent, скрипт существует в `profiles/watcher/scripts/` и лежит там настоящим файлом, а не симлинком, — та самая ловушка из лекции.
4. **Здоровье тикера.** `hermes gateway list` (оба профиля на месте), `cron status`, свежесть `cron/ticker_heartbeat` у worker и watcher и время последнего отчёта в `cron/output/` — мини-версия диагностической лесенки из лекции: тех же четырёх шагов проверки на случай «агенты встали».
5. **Итоговая сводка.** Все вердикты одним списком: её вывод вы и сдаёте.

## ДЗ к модулю

Шаги задания — в лекции, раздел «Домашнее задание». Критерии приёма — ниже, все проверяются без преподавателя:

- [ ] Крон worker — `every` с `Repeat: ∞`; «once in» в `jobs.json` нет.
- [ ] Вотчдог watcher — no-agent, скрипт лежит реальным файлом в `scripts/` профиля, не симлинком.
- [ ] `hermes gateway list` показывает worker и watcher; `ticker_heartbeat` обоих профилей свежий. Отчёты в `cron/output/` ноутбук только печатает — их появление после первых тиков проверяете глазами.
- [ ] Ноутбук проходит `Run all` целиком; вывод итоговой сводки — в чат курса как `[Модуль 19.1, ДЗ]`.

Бонус без проверки ноутбуком: `hermes webhook subscribe <имя> --prompt "..." --script gate.sh` — гейт-скрипт здесь работает привратником: событие, на которое он ничего не напечатал (пустой stdout), гасится, и агента не будят; вызов проверяется через `hermes webhook test`.

## Подводные камни

- **Кроны созданы, а `cron/output/` пуст и `ticker_heartbeat` не появляется.** Не запущен gateway профиля — тикер крона живёт именно в нём (сам `hermes cron create` предупреждает: «Gateway is not running — jobs won't fire automatically»). Лечение: `hermes -p worker gateway install`, затем `hermes -p worker gateway start` (то же для watcher); на WSL, в Docker и Termux (если эти слова вам незнакомы — это не про вашу машину) — `hermes -p worker gateway run` в отдельном терминале. Проверка — `hermes gateway list`: оба профиля running.
- **Крон был, а утром `No scheduled jobs.`** Расписание было `once in` + промпт разрешал «нет работы — остановись»: одноразовый джоб исчез после срабатывания, перевзводить его стало некому — цепочка умерла на первом холостом ходе. Живые конвейеры — на `every` с `Repeat: ∞`.
- **Heartbeat свежий, а отчётов в `cron/output/` нет.** Живой тикер не значит живые джобы: `jobs.json` может быть пуст, тикать нечему. Сверяйте `cron list` и время последнего файла в `cron/output/` — живой тикер при старых отчётах означает «задания нет», а не «всё работает». Тикер живёт в gateway-процессе профиля: проверьте `hermes gateway list`, при странностях — `hermes doctor` (есть и `--fix`).
- **Вотчдог падает с «Blocked: script path resolves outside the scripts directory».** Скрипт — симлинк, то есть ссылка-ярлык вместо настоящего файла: Hermes вычисляет, куда ссылка ведёт на самом деле (резолвит реальный путь), и не пускает за пределы `scripts/` профиля. Коварство в том, что ручной прогон `python3 script.py` на симлинке проходит — подделку ловит только тикер. Скопируйте файл по-настоящему; проверка — `test -L` должен сказать, что это не ссылка.
- **Подписали webhook, а события не приходят.** Подписка — полдела: платформа webhook должна быть включена в gateway профиля, а на стороне источника события может отсекать релей — пересыльщик, который передаёт наружу только события из своего списка, — проверяйте цепочку с обоих концов. Это грабли бонусного шага; обязательная часть домашки webhook не трогает.
