# Модуль 13.6 — Skills: выученный инструмент, своими руками на smolagents

Домашка к Модулю 13.6 «Skills: выученный инструмент» — лекция на сайте курса.

Здесь вы руками собираете мини-runtime скиллов поверх smolagents — и видите progressive disclosure насквозь. Мир и tools достаются в наследство от [модуля 11.5](https://github.com/ITrubnikov/Train_of_Thought-homework/tree/main/notebooks/module-11-5-tool-design): тот же лесоруб в мок-лесу (класс `Forest`: сетка 5×5, узлы дерева и камня, рюкзак на 5, склад, кулдаун — чистый Python без сети) и финальный «хороший» набор `move` / `gather` / `deposit` / `get_map`. Новое — уровень выше: skills лежат настоящими файлами `skills/<name>/SKILL.md`, в контекст агента попадает только витрина (`name` + `description`), а тело подтягивается инструментом `load_skill`, когда задача совпала с описанием. Разрыв «без skill vs со skill» измеряете детерминированным харнессом, качество skill-файлов — линтером skill-lint по чек-листу A→H. На выходе — рабочая библиотека скиллов в ноутбуке и свой `SKILL.md` в памяти настоящего агента.

## Что вы делаете в ноутбуке (всё рабочее, `Run all` проходит целиком)

1. **Блок 1 — наследство 11.5 и симптом.** Мок-лес `Forest` и финальный «хороший» набор tools приезжают одной ячейкой, дословно из модуля 11.5 (кулдаун в ноутбуке 0.3 с вместо лекционной 1.0 — только ради времени `Run all`, правила те же). Симптом из лекции 13.6 — скриптовый агент «без процедуры»: рубит прямо на складе (`no_resource_here`, потерянный ход), делает два удара, решает «хватит» и сдаёт 2/5. Действия есть — умения нет.
2. **Блок 2 (ядро, keyless) — мини-runtime скиллов.** Записываете `supply-run` и `scout-map` настоящими файлами `skills/<name>/SKILL.md` (анатомия из лекции: frontmatter `name`/`description` + тело «шаги / грабли / проверка»), разбираете их учебным парсером (~25 строк, без pyyaml), собираете витрину — только `name` + `description`, ровно то, что живёт в контексте агента. Селектор — детерминированная замена модели, как скриптовый «агент» в 11.5, — выбирает skill по описанию: таблица скоров на четырёх задачах, порог отсекает мусор. Скриптовый исполнитель проходит шаги `supply-run` и сдаёт 5/5 (единственная ошибка — `inventory_full`, сигнал перехода, а не потеря); харнесс сводит разрыв «без skill vs со skill» в таблицу. Финал блока — «сломай описание»: `description` → «Помогает с игрой.» — и скилл мёртв; вернули — ожил. Тело не менялось ни на символ.
3. **Блок 3 (ядро, keyless) — линтер skill-lint A→H.** Восемь правил как код: frontmatter распарсился, kebab-case и лимиты полей (как у skills в Claude Code), триггер-шаблон «Применяй, когда», чёрный список размытых фраз, разделы «Шаги» / «Грабли» / «Проверка», тело без воды. `supply-run` и `scout-map` собирают 8/8; вариант с размытым описанием проваливает ровно D и E — сломан триггер, не тело.
4. **Блок 4 (опционально, нужен локальный сервер).** Пятый tool `load_skill` + `ToolCallingAgent` с витриной в instructions: живая модель сама решает подтянуть тело — progressive disclosure вживую. Проверки по фактам, а не по словам агента: вызовы `load_skill` — по `agent.memory`, результат — по `forest.stock`. Затем тот же «сломай описание», но судья — живая модель. Сервера нет — мягкий пропуск, keyless-прогон остаётся зелёным.
5. **Задачи** в конце: написать `stone-run` по образцу `supply-run` и развести «дерево»/«камень» селектором; измерить «отрыв триггера» god-skill `forest-master` и расщепить его (зеркало «god-tool → узкие tools» из 11.5, теперь на уровне процедур); довести «худой» `wood-run-v1` до 8/8 с фиксацией «до/после»; перенести свой skill в настоящую память агента по секции «Домашнее задание» лекции. Задачи 1–3 — на моке, без ключей; каждая содержит рабочий образец, который вы меняете под себя.

## Подводные камни

- **Первая ячейка требует интернета.** `smolagents` ставится с PyPI; в Kaggle без `Internet → On` установка молча не пройдёт, и импорт упадёт. В Colab интернет есть всегда; локально поставьте пакеты заранее.
- **`@tool` читает исходный код.** Декоратор смотрит на текст функции через `inspect.getsource` — в ячейке ноутбука и в `.py`-файле это работает, а в голом REPL или `exec`-строке упадёт с `OSError: could not get source code`. Пишите tools в ячейках как есть.
- **Парсер SKILL.md — учебный, а не YAML.** Он понимает ровно тот формат, что в ноутбуке: `name:` со значением в строке и `description:` — в строке или свёрнутым блоком `>-`. Шаг влево (кавычки, вложенные поля, табуляция вместо пробелов) — и файл не распарсится; линтер поймает это правилом A. В бою берите настоящий парсер фронтматтера (`python-frontmatter`, `pyyaml`), а учебный держите как окно в механику.
- **Селектор — скриптовая замена модели.** В бою описание читает сама модель, и никакого «скора» вы не увидите. Совпадение по префиксам слов — честная учебная модель триггера: она делает выбор воспроизводимым и даёт число (отрыв), но стандартом не является. Не переносите формулу в прод — переносите вывод: описание пишется словами тех задач, которые оно должно ловить.
- **При равных скорах селектор берёт первого по алфавиту.** Это сознательная лотерея, показывающая цену нулевого отрыва: реальная модель при двух одинаково подходящих описаниях тоже выбирает непредсказуемо. Лечится не тай-брейком, а точным описанием.
- **Кулдаун в ноутбуке 0.3 с, в лекции — 1.0.** Уменьшен только ради времени `Run all`; правила и коды ошибок идентичны. Повтор раньше времени отбивается `on_cooldown` с точным временем ожидания.
- **Блок 4 без локального сервера — это норма.** Нет Ollama/LM Studio — блок печатает причину и идёт дальше (детект — два коротких запроса к localhost). Если сервер есть, но модель не умеет tool calling или споткнулась, ячейка сделает мягкий пропуск с текстом ошибки. Совсем маленькие и не-instruct модели вызовам инструментов не обучены — берите instruct от ~7B.
- **Эксперименты «сломай описание» правят файл на диске.** Ячейки Блока 2 и Блока 4 перезаписывают `skills/supply-run/SKILL.md` и возвращают его обратно (в живом варианте — в `finally`). Если вы прервали выполнение на середине и файл остался сломанным — перезапустите ячейку записи скиллов из Блока 2, она восстановит библиотеку.
- **Задача 4 проверяется не в ноутбуке.** Ячейка только собирает заготовку в `export-for-claude/`; подтянулся ли skill — смотрите у себя в агенте (Claude Code объявляет «Using \<skill\>…»). В Colab/Kaggle заготовку придётся скачать, локально — просто скопировать папку.
