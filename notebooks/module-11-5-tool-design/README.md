# Модуль 11.5 — Дизайн инструментов: чиним tools на моке Cognopolis

Домашка к [Модулю 11.5: Дизайн инструментов: что значит «хороший tool»](https://itrubnikov.github.io/Train_of_Thought/docs/modules/11-5-tool-design/).

Здесь вы руками превращаете «плохой» набор tools в «хороший» на моке игры [Cognopolis](https://kindomklaster.com). Собираете мок-мир (грид 7×7, ресурсы, инвентарь, кулдаун — чистый Python без сети), ставите рядом god-tool `do_action(action, target)` и расщеплённые инструменты (`move_dir` / `gather` / `fight` / `craft` / `heal_at_temple`) по живому API игры, а затем измеряете разницу детерминированным харнессом и оцениваете спецификацию линтером по чек-листу A→H. На выходе — рабочие функции в ноутбуке и навык видеть tool глазами модели.

## Что нужно сделать до начала

- **Ключи не нужны.** Базовый прогон (Блоки 1–2 и все Задачи) работает целиком на чистом Python без сети и без API-ключей.
- Аккаунт Colab или Kaggle (или локальный Python 3.10+). GPU не нужен.
- Желательно — прочитать лекцию модуля 11.5 хотя бы до секции «Хороший error учит».
- Опционально, только для Блока 3: ключ `MINIMAX_API_KEY` (живая модель MiniMax-M3). Без ключа блок делает мягкий пропуск.

## Что вы делаете в ноутбуке (всё рабочее, `Run all` проходит целиком)

1. **Блок 1 — мок-мир и два набора tools.** Собираете грид 7×7 с раскладкой из сидера игры (дом с авто-банком, деревья, камни, гоблин), правилами D-069 (движение — 8 направлений одним шагом, добыча и бой — на своей клетке) и кулдауном. Рядом — god-tool `do_action` (свободные строки, немые ошибки `{"error":"invalid"}`) и пять «хороших» split-инструментов с `Pydantic`-схемами, `enum`-направлениями, обучающими ошибками (`code` + дословный `message` живого сервера) и кулдауном.
2. **Блок 2 (ядро, keyless) — харнесс и линтер.** Детерминированный скриптовый «агент» гоняет один сценарий «добыть и принести домой (авто-банк)» через оба набора; вы видите в табличке разницу в доле успешных вызовов и в восстановлении после ошибки — и то, что «хороший» ответ сообщает про авто-банк полем `banked`, а «плохой» молчит. Затем мини-линтер по чек-листу A→H (правила как код) оценивает спецификацию tool в баллах: `do_action` набирает мало, `gather` — максимум.
3. **Блок 3 (опционально, нужен ключ).** Живая модель MiniMax-M3 (OpenAI-совместимый протокол) получает оба набора в формате tools и решает задачу «добудь дерево» — видно глазами, как `enum` и говорящее имя ведут модель прямо к цели. Без ключа — мягкий пропуск.
4. **Блок 4 (опционально).** «Хорошие» tools против живого API `https://kindomklaster.com`: токен вашего жителя (Ратуша → вкладка «аккаунт»), настоящие `move_dir` и `gather` — тот же конверт и те же ошибки, что в моке. Сервер недоступен или токена нет — мягкий пропуск.
5. **Задачи** в конце: переписать god-tool в узкий инструмент (образец `heal_at_temple`), превратить полуслепую ошибку `unknown_recipe` в обучающую с листингом каталога, сделать мутацию идемпотентной через `idempotency-key`, перегнать линтер до целевого score 8/8. Все задачи работают на моке без ключей; каждая содержит рабочий образец, который вы меняете под себя.

## Подводные камни

- **Кулдаун требует паузы.** После любого мутирующего tool персонаж «занят» 1 секунду; повтор раньше времени отбивается ошибкой `character_on_cooldown`. В харнессе между ходами стоит честный `time.sleep(_cooldown_left(w))` — поэтому сценарий не мгновенный. Это фича, а не тормоз: ровно так кулдаун защищает мир от дубля на ретрае.
- **`enum` навязывает форму, но не смысл.** `Pydantic` не пропустит `direction="up"` или `resource="timber"`, но `move_dir("north")` пройдёт схему, даже если житель стоит у северного края карты. За «можно ли вообще так» отвечает уже логика tool и его обучающая ошибка (`at_map_edge` называет направление, в котором упёрлись), а не схема.
- **`pydantic` v1 vs v2.** Ноутбук писался под `pydantic` 2.x (в Colab/Kaggle стоит он). Текст сообщения валидации в v1 чуть другой, но логика рельсов та же — ноутбук от версии не зависит.
- **Блок 3 без ключа — это норма.** Нет `MINIMAX_API_KEY` (или нет пакета `openai`, или нет сети) — блок печатает «пропущено» и идёт дальше. Ключ кладите в Secrets/переменную окружения, никогда в код.
- **Блок 4 и живой сервер.** API `https://kindomklaster.com` — учебный инстанс и может быть недоступен или на паузе. Блок делает мягкий пропуск с коротким таймаутом, keyless-прогон от этого не краснеет. Ходите токеном своего жителя (`COGNOPOLIS_TOKEN`) — чужих персонажей вы не трогаете.
- **Линтер судит спецификацию, а не код.** Он читает «паспорт» tool (словарь с флагами поведения), а не разбирает реализацию. Это намеренно: так же по описанию tool судит и сама модель. Меняя спецификацию, держите её честной по отношению к тому, что tool реально делает.
