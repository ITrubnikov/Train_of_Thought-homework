# Модуль 11.5 — Дизайн инструментов: лесоруб и хорошие tools на smolagents

Домашка к Модулю 11.5 «Дизайн инструментов: что значит „хороший tool"» — лекция на сайте курса.

Здесь вы руками превращаете «плохой» набор tools в «хороший» — на том же сквозном герое, что и в лекции: агент-лесоруб в мок-лесу. Собираете лес (класс `Forest`: сетка 5×5, узлы дерева и камня, рюкзак на 5, склад, кулдаун — чистый Python без сети), ставите рядом god-tool `do_action(action, target)` и четыре инструмента по одной цели (`move` / `gather` / `deposit` / `get_map`) на smolagents — сначала через `@tool`, затем с апгрейдом до subclass `Tool` с `enum` в схеме, обучающими ошибками `{code, message}` и конвертом `{result, cooldown, state}`. Разницу измеряете детерминированным харнессом и линтером по чек-листу A→H. На выходе — рабочие tools в ноутбуке и навык видеть контракт глазами модели.

## Что вы делаете в ноутбуке (всё рабочее, `Run all` проходит целиком)

1. **Блок 1 — мок-лес и два набора tools.** Класс `Forest` дословно из лекции (кулдаун в ноутбуке 0.3 с вместо лекционной 1.0 — только чтобы `Run all` укладывался в минуту, правила те же). Антигерой — god-tool `do_action` через `@tool`: docstring честный, smolagents собирает схему без жалоб, а модель всё равно обречена угадывать строки. Герой строится по арке лекции: имена по одной цели через `@tool` → `enum` в схеме через subclass `Tool` → обучающие ошибки (`no_resource_here`, `inventory_full`, `not_at_storehouse`, `on_cooldown`) → конверт `{result, cooldown, state}` → кулдаун на всех мутациях. По дороге вы распечатываете контракт глазами модели (`tool.name` / `tool.description` / `tool.inputs`) и JSON-схему с `enum`, которую получает `ToolCallingAgent`.
2. **Блок 2 (ядро, keyless) — харнесс и линтер.** Детерминированный скриптовый «агент» гоняет один сценарий — «найди дерево → дойди → руби до `inventory_full` → вернись → `deposit`» — через оба набора. В табличке — доля успешных вызовов, восстановление после ошибки и потерянные ходы: на хорошем наборе каждая ошибка конвертируется в следующий ход, на плохом каждая — тупик. Затем мини-линтер по A→H (правила как код) читает спецификацию прямо из smolagents-объектов: `do_action` набирает 2/8, финальный `gather` — 8/8.
3. **Блок 3 (опционально, нужен локальный сервер).** Живая модель через `OpenAIServerModel` + `ToolCallingAgent` решает задачу «добудь дерево и сдай на склад» тем же хорошим набором — видно, как `enum` и говорящие имена ведут модель к цели. Всё локально, без единого токена: ячейка сама находит Ollama или LM Studio; сервера нет — мягкий пропуск. Куда дальше с этим кодом — два ноутбука-приложения рядом: [`local-agent.ipynb`](local-agent.ipynb) (тот же локальный маршрут не спеша: выбор сервера, выбор модели, оговорки) и [`to-hf-space.ipynb`](to-hf-space.ipynb) (тот же агент — веб-чатом на HF Spaces, для желающих дать ссылку друзьям).
4. **Блок 4 (опционально).** Те же принципы против живого API игры `https://kindomklaster.com`: настоящие `move_dir` (enum из 8 направлений вместо 4) и `gather` — те же пары `{code, message}` и тот же конверт, только поле называется `character`, а не `state`. Сервер недоступен или нет токена — мягкий пропуск.
5. **Задачи** в конце: переписать спрятанный в `do_action` крафт топора в узкий tool `craft_axe` по образцу `deposit`; сделать ошибку `unknown_recipe` обучающей — с листингом каталога рецептов прямо в `message` («enum в форме ошибки»); реализовать идемпотентность `gather` через `idempotency-key`; догнать «худую» спеку `chop_tree` линтером до 8/8 с фиксацией «до/после». Все задачи на моке, без ключей; каждая содержит рабочий образец, который вы меняете под себя.

## Подводные камни

- **Первая ячейка требует интернета.** `smolagents` ставится с PyPI; в Kaggle без `Internet → On` установка молча не пройдёт, и импорт упадёт. В Colab интернет есть всегда; локально поставьте пакеты заранее.
- **`@tool` читает исходный код.** Декоратор смотрит на текст функции через `inspect.getsource` — в ячейке ноутбука и в `.py`-файле это работает, а вот в голом REPL или `exec`-строке упадёт с `OSError: could not get source code`. Пишите tools в ячейках как есть.
- **Docstring — часть контракта, и smolagents это проверяет.** У функции под `@tool` каждый аргумент обязан быть описан в блоке `Args:` — иначе `DocstringParsingException`. У subclass `Tool` каждый вход в `inputs` обязан иметь ключи `type` и `description`, параметры `forward` должны совпадать с ключами `inputs`, а у параметра с дефолтом — стоять `"nullable": True`.
- **`enum` — рельсы до вызова, а не валидация на входе.** smolagents кладёт `enum` в схему (модель видит список заранее), но жёстко значения не проверяет: `move(direction="up")`, если модель всё же его пришлёт, дойдёт до вашей логики. Редкий промах должна ловить логика tool и её обучающая ошибка — в ноутбуке это показано отдельной ячейкой.
- **Кулдаун в ноутбуке 0.3 с, в лекции — 1.0.** Уменьшен только ради времени `Run all`; правила и коды ошибок идентичны. Повтор раньше времени отбивается `on_cooldown` с точным временем ожидания.
- **Блок 3 без локального сервера — это норма.** Нет Ollama/LM Studio — блок печатает причину и идёт дальше (детект — два коротких запроса к localhost). Если сервер есть, но модель не умеет tool calling или споткнулась, ячейка сделает мягкий пропуск с текстом ошибки. Совсем маленькие и не-instruct модели вызовам инструментов не обучены — берите instruct от ~7B.
- **Блок 4 и живой сервер.** `https://kindomklaster.com` — учебный инстанс и может быть недоступен. Блок делает мягкий пропуск с коротким таймаутом, keyless-прогон от этого не краснеет. Ходите токеном своего жителя — чужих персонажей вы не трогаете.
- **Линтер судит контракт плюс честный «паспорт».** Имя, описание и аргументы он читает из настоящего smolagents-объекта (`tool.inputs`), а поведение (форма ошибок, конверт, идемпотентность) — из декларации `meta`. Меняя `meta`, держите её честной по отношению к тому, что tool реально делает, — иначе обманете не линтер, а себя.
