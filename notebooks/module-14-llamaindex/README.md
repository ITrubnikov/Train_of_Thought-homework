# Модуль 14 — LlamaIndex: агент над вашими данными

Домашка к Модулю 14 «LlamaIndex — когда у тебя много данных» — лекция на сайте курса. Модуль дополнительный: можно пропустить, если вы за минуту объясните разницу между query engine и агентом с QueryEngineTool — и покажете, какой из них ответит при выключенном LLM-сервере (спойлер из лекции: никакой — без LLM отвечает только retriever).

Сквозной пример — «картотека персон»: 50 коротких описаний людей из публичного датасета `dvilasuero/finepersonas-v0.1-tiny` (тот же корпус, что в Unit 2.2 курса Hugging Face agents-course). Вы прогоняете его по всей лестнице LlamaIndex: файлы → `Document` → `Node` → Chroma → индекс → retriever (поиск по смыслу без LLM — главный keyless-момент модуля) → query engine (ответ словами) → `FunctionTool` и `QueryEngineTool` → агент, который сам решает, когда лезть в базу, а когда посчитать файлы, — со стримингом его решений и памятью через `Context`. Реальный двойник картотеки — база профилей клиентов в саппорте или CRM; в домашней доработке двойник становится буквальным: второй индекс над публичным годовым отчётом (SEC filing).

## Что нужно сделать до начала

- **API-ключи не нужны.** Ядро (Блоки 1–4, FunctionTool-часть Блока 7, Задачи 1–2 и retriever-части Задач 4 и 6) работает целиком без ключей: эмбеддинги считаются локально на CPU.
- **Python 3.10+.** В Colab/Kaggle это уже так; локально проверьте `python --version` (системный python3 на macOS — 3.9, не подойдёт), запасной путь — `uv venv --python 3.11`. Первая ячейка проверит версию сама.
- Аккаунт Colab или Kaggle — или локальный Python. GPU не нужен.
- **Интернет при первом прогоне:** библиотеки, датасет персон (при недоступности Hub сработает встроенный fallback из 10 персон) и один раз — веса embedding-модели `BAAI/bge-small-en-v1.5` (~130 МБ, дальше кэш).
- Опционально, для Блоков 6–7 и Задач 3–6: локальный OpenAI-совместимый сервер модели из Модулей 6.1/6.2 — LM Studio (порт 1234) или Ollama (порт 11434) с instruct-моделью, умеющей tool calling (например, `qwen2.5:7b`). Без сервера эти блоки делают мягкий пропуск, keyless-прогон остаётся зелёным.

## Что вы делаете в ноутбуке (`Run all` проходит целиком)

1. **Блок 1 (ядро, keyless) — корпус.** Срез 50 персон из публичного датасета пишется в `data/*.txt`; при недоступном Hub — встроенный fallback из 10 персон. Двойник — выгрузка профилей клиентов из CRM.
2. **Блок 2 (ядро, keyless) — Document → Node.** `SimpleDirectoryReader` и `IngestionPipeline` из `SentenceSplitter` + `HuggingFaceEmbedding`: нарезка и эмбеддинги, которые в модуле 7 вы делали руками.
3. **Блок 3 (ядро, keyless) — Chroma и индекс.** Персистентная база `./m14_chroma_db`, коллекция `personas`, `VectorStoreIndex` поверх; защита от задвоения при повторном прогоне.
4. **Блок 4 (ядро, keyless) — retriever.** Поиск по смыслу без LLM: два запроса, включая запрос без единого общего слова с найденной карточкой. Гвоздь ноутбука.
5. **Блок 5 (keyless-safe) — автодискавери модели.** Опрос LM Studio/Ollama, поддержка `LOCAL_API_BASE`/`LOCAL_MODEL_ID`, конструктор `OpenAILike`; без сервера — честный `[skip]`.
6. **Блок 6 (опционально, нужен локальный сервер) — query engine.** Тот же вопрос, что в Блоке 4, — теперь связным текстом (`response_mode="tree_summarize"`).
7. **Блок 7 (tool — keyless, агент — нужен сервер) — данные становятся инструментом.** `FunctionTool` и `tool.call()` без LLM; затем `QueryEngineTool` + `AgentWorkflow`: два вопроса, стриминг `ToolCallResult` показывает выбор инструмента; память через `Context`.
8. **Блок 8 — сводка прогона.** Таблица «блок → ran/skipped» — самопроверка перед сдачей.
9. **Задачи** — шесть доработок по нарастающей: свои документы, метаданные и фильтры, ломка description, второй индекс над годовым отчётом (артефакт ДЗ), оценка качества `FaithfulnessEvaluator`, тюнинг retrieval.

## Подводные камни

- **Первый запуск долго «молчит» на Блоке 2.** Качаются веса эмбеддера `BAAI/bge-small-en-v1.5` (~130 МБ) — это разовая загрузка, дальше работает локальный кэш.
- **Повторный прогон не задваивает базу, но смена корпуса требует чистки.** Блок 3 наполняет коллекцию только если она пуста (проверка по `count()`). Если вы сменили корпус — добавили свои файлы или переключились между fallback и полным срезом, — удалите папку `m14_chroma_db/` или соберите индекс в новой коллекции, иначе retriever будет искать по старым данным.
- **`query()` без сервера не работает — так и задумано.** Синтез ответа требует LLM; без сервера живёт только retriever (Блок 4). Это не поломка, а главное различие двух дверей к индексу.
- **Агент не вызывает tools.** Ваша локальная модель не умеет function calling. Лекарство: взять instruct-модель с tool calling (например, `qwen2.5:7b`) — или собрать агента через `ReActAgent` (импорт из `llama_index.core.agent.workflow`), он работает с любой моделью через текстовый цикл рассуждений.
- **sec.gov отдаёт 403 (Задача 4).** Нет заголовка `User-Agent` с контактом — правило EDGAR для роботов. В образце кода задачи заголовок уже прописан: впишите свой контакт.
- **Слишком мелкий `chunk_size` ломает нарезку.** Демо-значение `chunk_size=25` из оригинального ноутбука Unit 2.2 не срисовывайте: сплиттер учитывает и метаданные файла, при крошечных чанках получите ошибку вида «metadata length exceeds chunk size». Рабочий диапазон для этого модуля — 256–512.
- **Kaggle без `Internet → On` падает на первой ячейке.** Установка пакетов, датасет и веса эмбеддера приходят из сети; включите интернет в настройках ноутбука (phone-verified аккаунт).
- **Эмбеддинг идёт минуты, а не секунды.** Вы проиндексировали не срез, а весь датасет (5000 персон) — или целиком большой PDF в Задаче 4 с крошечным `chunk_size`. Ядру хватает 50 персон; так и задумано в Блоке 1.
